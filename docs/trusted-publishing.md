# GitHub Actions trusted publishing

Register the repository, product, tag/environment identity and hosted-signing policy with the private SocketJack publisher before using this workflow. Enable `id-token: write` only in the publishing job; keep environment protections in place. The generic client requests a fresh GitHub identity for audience `https://socketjack.com/installer-publisher`, exchanges it for a short-lived package-scoped credential, and never stores it or prints it. No publisher password, publisher access token or durable signing key belongs in the workflow.

For the tag-triggered template, register workflow path `owner/repository/.github/workflows/publish-installer.yml` without an `@` suffix, allowed ref `refs/tags/v*`, environment `installer-publishing`, and the repository's actual numeric repository/owner IDs. One policy then accepts successive tags: `v2026.10.25.1` authorizes package version `2026.10.25.1`, and the next numeric tag authorizes its matching version. The verified workflow reference must equal that exact path plus `@` and the verified triggering ref. The tag wildcard never authorizes a different package version, branches, pull requests, or forks. Exact branch/tag refs and legacy full workflow references keep exact matching; an optional reusable workflow pin must include its exact full reference (prefer a commit SHA).

Use the [tag-triggered workflow template](../templates/github-actions/trusted-publish.yml.example) with the application's existing installer build steps and its verified installer CLI distribution. Pin Actions to reviewed commit SHAs in the consuming repository. The template assumes an already-installed CLI; build/install that tool through the repository's established tooling before its publish step. Configure the required release environment and repository identity on the private service. A GitHub OIDC token authenticates the workflow; it does not automatically authorize an unregistered repository or product.

```powershell
heirowInstaller.Cli publish ./artifacts/draft.hinst --publisher https://socketjack.com --github-oidc --wait-for-activation
```

The API equivalent is `PublisherClient.PublishFromGitHubActionsAsync(packagePath, productId, version, options, cancellationToken)`. Use a connection without browser/account credentials. The client hashes and uploads the same read-locked file in bounded chunks. It checks GET upload state before transfer, resumes from the exact acknowledged offset, and renews credentials for the same upload/product/version/digest. Failed OIDC transfers remain on the service for bounded resume rather than being deleted. An explicit known upload can be resumed with `--resume-upload <id>`; repeating the same version and input digest reuses its receipt. The same version with different input is a conflict.

Receipts distinguish submission from activation: `status` is `pending`, `activated`, or `rejected`. `uploadedPackageSha256` and `uploadedSize` identify the original input; `sha256` and `size` identify the final sealed installer and can differ. Submission alone never means the application is available. `--wait-for-activation` polls the same receipt until active, rejected, cancelled or its 15-minute wait deadline. A timeout leaves the submission pending; it does not cancel server review. Existing release signature pins remain authoritative for installed delivery.

## Protected input descriptor

Place the declarative descriptor under `Modules.SocketJackSecurityLoader` in the input manifest. `formatVersion` is 1. Each component declares `id`, exact payload `sourcePath`, `executionMode` (`remote` or `local`), `entryType`, `runtime` (`net10.0` or `net8.0`), and component/assembly identifier `dependencies`. Operations map `id` to `componentId`. `publicPayload` explicitly identifies ordinary payload paths. `bootstrapPath` plus `bootstrapSha256`, when present, identify the private bootstrap carried by the signed final installer. The SDK validates paths and metadata; it contains no encryption, private worker implementation, or decryption keys.

An unsigned protected input is accepted by the CLI only when this descriptor explicitly requests `hostedSigning: true`; the service must independently authorize the registered hosted signer for that product. This input is not an installable trusted release. The private service seals protected content and signs the final package; clients install only the validated signed result. Omitted/false hosted signing retains ordinary signature requirements. Do not upload application-private sources to this public repository.

The C# and VB startup templates in `templates/bootstrap/SocketJackSecurityLoaderStartup.*` take the installed private bootstrap's asynchronous entrypoint as a delegate. Invoke and await them before enabling protected functionality. Initialization failures propagate; do not continue into protected features or add a plaintext DLL fallback. These templates carry no authentication or protected runtime implementation.
